# Journal recommendation and submission readiness

## Recommended venue

The recommended venue is the **Journal of Open Research Software (JORS)** as a **Software Metapaper**. The workbench is research software with a clear reuse case, synthetic sample inputs and outputs, an open license, deterministic tests, and an architecture that can be described concisely. JORS reviewers specifically assess implementation and architecture, quality control, reuse, licensing, sample data, installation, and support, which match the manuscript's revised structure ([JORS peer-review criteria](https://openresearchsoftware.metajnl.com/about/editorialpolicies)).

## Submission status

The manuscript should not be submitted yet. JORS requires the software to be freely available in a public repository under an open license and asks authors to include a persistent identifier for the deposited release ([JORS submission guidelines](https://openresearchsoftware.metajnl.com/about/submissions)). This local repository currently has no configured remote, public release, or archive DOI.

Before submission, the authors should publish a reviewed release, archive that exact version in a repository that issues a DOI, run installation and pilot reproduction from a clean environment, confirm the CRediT author-contribution statement, provide three independent reviewer suggestions and a cover letter, and confirm the source and permissions statement for Figure 1. The final release identifier should then replace the pre-release language in the manuscript and `CITATION.cff`.

The current manuscript treats synthetic pilot metrics as software quality-control evidence rather than biological research results. That framing is important because JORS Software Metapapers are concise descriptions of reusable research software, not substitutes for empirical research articles.
